## Порядок будущего мерджа

Это план после общей приёмки, не разрешение на GitHub merge. Default branch — `main`.
Сначала фиксируется итоговый integration HEAD, затем выполняются fresh combined
source/native/browser gates и CI для точного SHA. Принимаемые ограничения,
неподтверждённые device-пункты и backup/schema compatibility остаются видимыми.
После этого пользователь получает конкретный результат и порядок PR для
отдельного решения о merge.

`main` и проверить новый merge candidate. Массовый squash без подготовки
зависимых веток не входит в этот план.
