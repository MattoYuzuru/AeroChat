Если нужен новый небольшой runtime, подготовь конкретную новую owned область и cleanup, не копируй сотни drivers и не делай глобальную замену namespace цифр без проверки bindings. Результат failed receipt нельзя объявлять PASS; SOURCE_ONLY/Proposed не равны actual runtime.

## Как работать без накопления нового огромного контекста

Начни с одного короткого плана из конкретных изменений и проверок, затем исполняй. Работай последовательно, без автоматического запуска пяти агентов и без пересоздания старых чатов. Использовать помощников только для реально независимой небольшой задачи; передать им точный checkout/HEAD, AGENTS/skill paths, файлы/owner/lock/check scope. Не держать несколько владельцев одних frontend/RTC файлов.

Не создавать новую систему receipts вокруг каждого чтения или завершённого immutable артефакта. Сохранять достаточно evidence для нового изменённого кода и реального cleanup. Повторять gate только из-за нового diff/failure/обоснованной несовместимости. Следующий агент должен завершить ограниченный этап и выдать владельцу готовый локальный результат, оставшиеся ручные действия и отдельные deferred features, а не ещё один бесконечный исследовательский handoff.
